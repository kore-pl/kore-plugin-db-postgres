# Плагин управления PostgreSQL（kore-plugin-db-postgres）

## Обзор

Плагин действительно подключается к экземплярам PostgreSQL, перечисляет базы (с размерами), выполняет SQL только для чтения, считывает метрики состояния и медленные запросы, а также предлагает настраиваемый в интерфейсе контракт подключения, вступающий в силу при сохранении; начиная с 0.4.0 добавлены резервное копирование и восстановление (pg_dump в пользовательском архиве или текстовом SQL, pg_restore / psql; восстановление требует confirm=true и автоматического снимка целевой базы). Он не включает драйвер PostgreSQL и клиентские бинарники: уровень выполнения — подпроцесс `psql` хоста с переключением на `docker exec <контейнер> psql`, если локального `psql` нет.

## Поверхность протокола

Протокол `kore.plugin.v1`, возможность `system:admin`, взаимно исключает `db-mysql`. Методы: `config.get` / `config.set` / `instances` / `databases` / `query` / `status` / `slowlog`, методы записи `createDatabase` / `dropDatabase` / `createUser` / `dropUser` / `grant` / `changePassword` и методы резервного копирования `backup` / `restore` / `backupList` / `backupDelete` / `backupDownload`. Имена методов требуют префикс домена `db-postgres.`; другие домены возвращают `E_NOTFOUND`. Удаление требует явного `confirm=true`.

## Основные возможности

Приоритет конфигурации: `config.json` > окружение > значения в коде; пароли идут только через PGPASSWORD (режим psql) или первую строку stdin (режим docker exec), никогда в argv, ps или логи. Файлы резервных копий должны находиться в `KORE_DB_EXPORT_DIR` (по умолчанию `<state>/exports`), проверяются лексически и на символьные ссылки; `backupDownload` передаёт base64 блоками по 4 МиБ для сборки Blob на стороне интерфейса; список копий пропускает артефакты mysqldump по заголовку файла.

## Граница безопасности

Нулевая поверхность внедрения в shell: pg_dump / pg_restore / psql используют фиксированный argv, имена баз — только как позиционный аргумент, имена таблиц — только через `--table=`; пароли никогда не попадают в argv / ps / логи. Восстановление требует `confirm=true`, автоматически снимает снимок целевой базы (можно явно отключить) и может создать отсутствующую базу; текстовые восстановления обёрнуты в BEGIN/COMMIT для атомарности. Пути резервных копий проверяются лексически и на символьные ссылки, при ошибке не остаётся частичных файлов. Уровень глубины `basic`: граничные случаи и внедрение отказов отложены до v1.1.

## Сборка и проверка

Ежедневная проверка — локальный `make check` (gofmt → go vet → go test -timeout 200s); перед выпуском `make dist` дважды с совпадающим sha256. Сбой из-за типизированного nil имеет отдельный регрессионный барьер `internal/pgop/typednil_test.go`; у резервного копирования есть контрактные и граничные тесты. Версия 0.4.0; взаимно исключает `db-mysql` — не включать запись для обоих одновременно.
